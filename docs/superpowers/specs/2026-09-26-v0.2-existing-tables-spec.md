# Schema Grid v0.2 — grids over existing tables

Status: approved (2026-09-26). Source: integration review from the admissions app (4 admin pages cost ~1–2k lines each; the hand-written filter→SQL translation was most of it).

Goal: a new admin grid over an EXISTING table = one `defineGrid()` call on the server + one `<SchemaGridWorkbench>` on the page.

All packages stay in the Changesets fixed group → release is `0.2.0` for all six.

## Binding contracts (core unless stated)

### C1. Column options (`ColumnDef`)
- `sortable?: boolean` (default true), `filterable?: boolean` (default true), `settable?: boolean` (default true; false = visible/editable-by-permission but the DATA SOURCE cannot write it — e.g. computed "AI verified").
- Effective edit access = permission `edit` AND `settable !== false`. `resolveColumnAccess` returns `"read"` when `settable === false`.
- `validateFilter` rejects conditions on `filterable === false` columns (`code: "unfilterableColumn"`); server `assertQueryAccess` rejects sort on `sortable === false` (`PermissionError` usage `sort` → new code `UNSORTABLE_COLUMN`, 400).
- compileColumns: `sortable:false` → ColDef `sortable: false`; `filterable:false` → no filter component, hidden from filter builder pickers; `settable:false` → not editable, paste/fill skip it and count as `skippedReadOnly`.

### C2. Data-source capabilities
- `DataSourceCapabilities { maxPageSize: number; sort: "all" | { columnIds: string[] }; filter: "all" | { columnIds: string[] }; operators?: Record<columnId, string[]>; groupBy: boolean; search: boolean; changeFeed: boolean; write: { cells: boolean; createRows: boolean; deleteRows: boolean }; options: boolean; lookup: boolean; export: { maxRows?: number } }`
- `DataSource.capabilities?(): Promise<DataSourceCapabilities> | DataSourceCapabilities`. Wire op #9 `capabilities` (input `null`, output the object). `createRemoteDataSource` exposes it; `createDataSourceHandler` returns a computed default when the source lacks it.
- `DEFAULT_CAPABILITIES` (everything true/"all", maxPageSize 500). `mergeCapabilities(schema, caps)` intersects column options with caps → the grid's effective matrix.
- ag-grid: `useSchemaGrid` fetches capabilities once (and again after `onSchemaChanged`); turns off header sort on unsortable columns, hides filter affordances on unfilterable ones, hides Group button when `groupBy:false`, hides search when `search:false`, disables polling when `changeFeed:false`, makes cells read-only when `write.cells:false`, clamps page size to `maxPageSize` (server + export), and the export iterator continues while `rows.length > 0 || nextCursor` (never stops on a short page). Remove the sort-undo hack path.

### C3. Client-side write enforcement (security gap)
- `editController.submit` filters every `CellChange` through `canEditCell(row, columnId)` (permission edit + settable + not formula) BEFORE optimistic apply; rejected cells go to `ChangeResult.errors` with message "Read-only" and are counted in `ClipboardReport.skippedReadOnly` for paste/fill; undo/redo re-check at execution time (a column made read-only since the edit is skipped, not sent).
- Hidden columns can never be read from `rowStore` by paste/copy (copy skips them already; assert in tests).

### C4. `createSqlViewDataSource` (server, `./drizzle`)
```
createSqlViewDataSource({
  db, schema, registry?, resolver, user, tz?, now?,
  baseQuery: (ctx) => SQL | MySqlSelect,       // FROM/JOIN/WHERE base, no ORDER/LIMIT
  columns: Record<columnKey, { expr: SQL | AnyColumn; kind?: StorageKind; searchable?: boolean }>,
  rowId: SQL | AnyColumn,
  version?: SQL | AnyColumn,                  // omitted → optimistic check by full-row hash of settable cells
  updatedAt?: SQL | AnyColumn,                // enables updated_at change feed (C8)
  write?: {
    update?: (ctx, { rowId, changes, baseVersion }) => Promise<{ applied: CellChange[]; version: number } | { conflict: ChangeConflict }>,
    create?: (ctx, partials) => Promise<GridRow[]>,
    delete?: (ctx, ids) => Promise<void>,
  },
  defaultCapabilities?: Partial<DataSourceCapabilities>,
}) => DataSource<GridRow>
```
- Reuses the existing translators (`translateFilter/Search/Sort`, keyset/offset paging, grouping) via a `ColumnExprResolver` seam: refactor `resolveColumnExpr` so the JSON-cells resolver and a "mapped expression" resolver implement one interface. NO duplicated SQL logic.
- `write` absent → `capabilities.write = {cells:false,createRows:false,deleteRows:false}` and the grid becomes read-only automatically.
- Columns not in `columns` but present in the schema (extension columns, C7) are served from the extension store.
- Reference test: the MySQL integration suite runs the §8 filter, sort, cursor paging, grouping and parity against a plain `admissions_leads`-style table (create in the harness) with NO `cells` JSON.

### C5. `defineGrid` + one endpoint (server `./http`, core `./wire`)
- `defineGrid<Ctx>({ id, schema: GridSchema | (ctx) => Promise<GridSchema>, source: (ctx) => DataSource, permission?: (ctx, op) => boolean | Promise<boolean>, schemaStore?: SchemaStore })` → `GridDefinition`.
- `createGridRegistry(defs[])` → `{ handle(gridId, op, input, ctx), list(ctx) }`; unknown grid → `UNKNOWN_GRID` 404; `permission` false → `PERMISSION_DENIED` 403. Adds ops `getSchema` and `updateSchema` (validates with `assertValidSchema`, bumps `schemaVersion`, persists via `schemaStore`, runs DDL diff hook if provided) to the wire contract (#10, #11).
- Adapters: `toExpressRouter(registry, { context(req) })` mounting `POST /:gridId/:op` (+ `GET /:gridId/schema`), `toLambdaHandler(registry, …)`, and `toFetchHandler(registry, …)` (Web `Request → Response`, works for Hono/Bun/Next). Client: `createHttpDataSource({ baseUrl: "/grid/leads" })` unchanged; add `createGridClient({ baseUrl, gridId })` returning `{ dataSource, getSchema, updateSchema }`.
- demo-api switches to `defineGrid` + `toFetchHandler` (Hono) with TWO grids: the JSON-cells fixture grid and a SQL-view grid over a plain table.

### C6. Schema store
- `SchemaStore { get(gridId): Promise<GridSchema|null>; put(gridId, schema): Promise<void>; }` (core type). Server: `createDrizzleSchemaStore({ db, table })` + `createGridSchemasTableDDL({ table })` (`grid_id` PK, `schema` JSON, `schema_version`, `updated_at`). `defineGrid` uses it for `getSchema/updateSchema`; when the schema is static (object), `updateSchema` returns `UNSUPPORTED_OPERATION` 501 unless a store is given.
- The Workbench "+" add-column flow calls `updateSchema` → works out of the box with a store.

### C7. Extension columns beside existing tables
- `createExtensionCellStore({ db, table })` + `createExtensionCellsTableDDL({ table })`: `grid_id, row_id, cells JSON, version, updated_at, updated_by` (PK grid_id,row_id).
- `createSqlViewDataSource({ …, extension: store })`: schema columns without a mapped `expr` are read/written from the extension store, LEFT JOINed on `rowId` for filter/sort (reuse the JSON resolver on the joined `cells`), written via `applyChanges` with version checks on the extension row, and included in the change feed. Column permissions/options apply uniformly.

### C8. `updated_at` change feed
- For SQL-view sources with `updatedAt`: `getChanges(since)` = rows where `updated_at > since` (cursor = max `updated_at` ISO + last rowId tiebreak), deletes not detectable (documented; `capabilities.changeFeed = "updates-only"` → widen type to `boolean | "updates-only"`; grid then hides "row removed" handling and re-fetches on interval instead).

### C9. Drizzle peer range
- Peer `drizzle-orm: ">=0.41.0 <1"`. Only use APIs present in 0.41 (`sql`, `and/or/eq…`, `.toSQL()`, `db.transaction`, `mysqlTable`). CI matrix job installs 0.41 and 0.45 (alias `drizzle-orm@0.41` in a scratch dir or `bun install drizzle-orm@0.41.0` in the server package with `--no-save`) and runs the server unit suite for both.

### C10. `<SchemaGridWorkbench>` (ui-mantine; mirror in ui-shadcn as `<SchemaGridWorkbench>` too)
- Props: `client` (from `createGridClient`) OR `{ dataSource, schema, onSchemaChange? }`, `user`, `resolver?`, `title?`, `views` (controlled or `viewStore` prop with localStorage default), `features?: Partial<{ filter, group, search, views, export, import, addColumn, undo, polling }>` (auto-derived from capabilities, features can only turn OFF), slots: `toolbarStart`, `toolbarEnd`, `statusBar`, `emptyState`, `renderCell?(columnId)` override, `onError?`.
- Everything the Storybook `Workbench.tsx` does moves into this component; Storybook stories use it. Error states: capability-denied, permission-denied, network — inline banners with retry.

## Acceptance (end to end, demo-api + MySQL + Playwright)
1. A plain table `leads(id, name, email, payment_status ENUM, call_date DATE, ai_verified BOOL, updated_at)` is exposed with `defineGrid` + `createSqlViewDataSource` in ≤ 40 lines; page = `<SchemaGridWorkbench client={createGridClient(...)}/>`.
2. §8 filter works over it; sort on an unsortable column is impossible in the UI and rejected by the server; `ai_verified` shows but cannot be edited (settable:false) and paste over it reports skipped cells.
3. Add a column from the "+" header → persisted in the schema store, values stored in the extension table, filter/sort on it work, survive reload.
4. Export of 1,200 rows with `maxPageSize: 200` yields 1,200 rows.
5. Edit in tab A shows up in tab B via the `updated_at` feed.
6. Server unit suite green on drizzle 0.41 and 0.45.
